# ReentrantLock Educational Demo Project

Проект демонстрирует возможности и нюансы использования `java.util.concurrent.locks.ReentrantLock` — современного механизма блокировок в Java.

## Цель проекта
Предоставить образовательный ресурс для глубокого понимания многопоточности в Java, следуя принципу "от простого к сложному".

## Состав проекта
1.  **BasicLockDemo**: Основы использования `lock()` и `unlock()`, критическая важность блока `try-finally`.
2.  **TryLockDemo**: Неблокирующая попытка захвата замка, использование таймаутов для предотвращения Deadlock.
3.  **ConditionDemo**: Взаимодействие потоков (Producer-Consumer) через `Condition`, замена `wait/notify`.
4.  **AdvancedFeaturesDemo**: Концепция повторного входа (Reentrancy), инспекция состояния замка (Hold Count, Fairness).
5.  **ReentrantLockPitfallsTest**: Набор тестов, демонстрирующих "подводные камни", такие как прерываемость и справедливость.

## Технологический стек
- **Java 21**: Использование современных возможностей языка.
- **Gradle (Kotlin DSL)**: Сборка и управление зависимостями.
- **JUnit 5**: Тестирование многопоточных сценариев.
- **SLF4J + Logback**: Наглядное логирование работы потоков.

## Настройка и запуск

### Требования
- JDK 21 или выше.
- Доступ в интернет (для загрузки Gradle и зависимостей).

### Сборка проекта
```bash
./gradlew build
```

### Запуск демонстрации
Основной демонстрационный класс `Main` запускает последовательность примеров:
```bash
./gradlew run
```

### Запуск тестов
Тесты содержат важные проверки поведения `ReentrantLock`:
```bash
./gradlew test
```

## Критические рекомендации (Best Practices)
1.  **Всегда** используйте `try-finally` для вызова `unlock()`.
2.  Вызывайте `lock()` **непосредственно перед** блоком `try`.
3.  Для `Condition.await()` всегда используйте цикл `while`, проверяющий условие.
4.  Помните, что `tryLock()` без аргументов не соблюдает очередь "честного" замка (barging).
